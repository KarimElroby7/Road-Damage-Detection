1. Objective

Build, compare and deploy an AI system that detects and localizes road damage in images using YOLO-based object detection. The project covers:

  • Training three YOLO generations — YOLOv8s, YOLO11s and YOLO26s — on the same data with the same settings.
  • Comparing them on mAP, precision / recall, IoU, inference speed (FPS), model size and deployment efficiency (ONNX export).
  • A comparative analysis of the results.
  • A deployment application (FastAPI backend + web dashboard) for image-based and real-time detection.

Detected classes: Crack, Manhole, Pothole. Manholes are not damage, but detecting them explicitly prevents the model from confusing round manhole covers with potholes.

2. Dataset and preparation

The data is managed in a Roboflow project (project-dvd12/road-damage-eul7g). It combines road-damage images (cracks, potholes, manholes) with an additional set of manhole images to balance the classes. The project holds 4,643 images and 6,323 bounding boxes.

2.1 Data cleaning

  • Unlabeled images removed. The dataset health check reported 802 "null" images (no annotations). Manual inspection showed that most of them actually contain visible manholes and potholes that were never labeled. Training on them would teach the model that these objects are background, so they were tagged unlabeled and excluded with a Filter by Tag step (not deleted).
  • Class names unified. manholes was renamed to Manhole (2,116 labels) to match Crack and Pothole.
  • No missing annotations remained in the final version.

4. Evaluation protocol

To make the comparison fair, all three best.pt files were evaluated with one script (evaluation/evaluate.py) on the same 429 test images (never used for training or model selection) and on the same machine: NVIDIA GeForce RTX 3060 Laptop GPU (6 GB) and Intel Core i5-11400H CPU, PyTorch 2.14 + CUDA 13.0.

MetricHow it is measured
mAP50, mAP50-95Ultralytics validation on the test split (IoU threshold 0.5, and averaged over 0.5–0.95)
Precision, RecallMean over classes at the confidence that maximizes F1
Mean IoUPredictions (conf ≥ 0.25) matched greedily to the same-class ground-truth box with the highest IoU (≥ 0.5); average IoU of these true positives = localization quality
Inference speed / FPSBatch size 1, average over all test images (pre-process + inference + post-process). GPU in FP16, CPU in FP32, 10 warm-up images
Model sizebest.pt file size, number of parameters, GFLOPs at 640×640
Deployment efficiencyExport to ONNX; ONNX file size, CPU speed with ONNX Runtime, and test mAP of the ONNX model (accuracy kept after export)

6. Comparative analysis and discussion

6.1 Accuracy

  • The newer the generation, the more accurate: YOLO26s > YOLO11s > YOLOv8s on mAP50 (0.654 / 0.636 / 0.622), mAP50-95 (0.376 / 0.361 / 0.346) and mean IoU (0.790 / 0.784 / 0.782). The ranking is consistent across all accuracy metrics, although the gaps are moderate (+3.2 mAP50 points from YOLOv8s to YOLO26s).
  • YOLO26s is clearly the most precise (0.761 vs ≈0.70): it produces fewer false alarms at a similar recall (≈0.60–0.62). For a road-inspection tool this means fewer wasted inspections.
  • Localization is similar for all models (mean IoU ≈0.78–0.79): when a damage is found, the box is tight in every case; the differences come mainly from what is found.

6.2 Per-class behaviour

  • Manhole is easy (AP50 ≈0.89–0.90, recall 0.87): manhole covers have a distinctive round shape and texture.
  • Pothole is moderate (AP50 ≈0.68–0.71): the boundary of a pothole is not well defined, which lowers AP50-95.
  • Crack is the hardest class (AP50 0.29–0.36, recall ≈0.30–0.33). Cracks are thin, long and low-contrast; a single crack may be annotated as one box in one image and as several pieces in another; and an axis-aligned box around a diagonal crack is mostly background. These effects make both detection and the IoU-based AP50-95 difficult. YOLO26s gives the largest improvement exactly on this class (+6.3 AP50 points over YOLOv8s).
  • Confusions between classes are rare (≤7%); the dominant error is crack vs. background, not crack vs. pothole.

6.3 Speed and size

  • All three models run in real time on the GPU (53–84 FPS in FP16, batch 1). YOLOv8s is the fastest (11.9 ms per image) despite having the most parameters and FLOPs; the newer architectures use extra attention-style blocks that improve accuracy but add latency at batch size 1.
  • On the CPU the models are almost equal (≈9–10 FPS). YOLO11s is the lightest model (9.4 M parameters, 19.2 MB) and the fastest on the CPU.
  • ONNX export keeps the accuracy (drop ≤ 0.008 mAP50-95; only 0.002 for YOLO26s), so every model can be deployed without PyTorch. On this CPU, ONNX Runtime was not faster than PyTorch; its benefit is portability (no PyTorch dependency, runs on edge runtimes).

Selected model: YOLO26s. It is the most accurate (highest mAP, precision and IoU, and the best crack detector), keeps its accuracy after ONNX export, and is still real-time on the GPU (53 FPS). It is the default model of the deployment app.
When to choose another model: YOLOv8s when maximum GPU throughput matters more than accuracy (e.g. many camera streams); YOLO11s for CPU-only or memory-constrained devices (smallest and fastest on CPU). All three are available in the app.

6.5 Limitations

  • Label noise. The data was merged from several sources. Some drains and manholes are still unlabeled (Figure 8, third row: the models detect drain grates that have no ground-truth box), so part of the measured "false positives" are correct detections. About 6% of the test images (25 / 429) are stock photos or illustrations rather than real road images.
  • Crack annotations are inconsistent (one box vs. several boxes per crack), which limits the achievable crack AP for every model.
  • Test-set size. With 429 test images, differences of about 0.01 mAP between models are within normal variation; the overall ranking is consistent across metrics, but small gaps should not be over-interpreted.

7. Deployment application

The selected models are served by a FastAPI backend with a web dashboard (folder road_damage_app/).

→

→
FastAPI backendPOST /api/detect
→
YOLO modelsv8s · 11s · 26s (GPU FP16)
→
Detection resultsJSON: class, conf, box

Backend (FastAPI)

  • Loads all three models once at start-up on the GPU (FP16), or on the CPU if no GPU is present; .onnx files are supported too.
  • GET /api/models — available models and the default (YOLO26s).
  • POST /api/detect — image + model, conf, iou, imgsz; returns boxes, class, confidence, counts per class and timing.
  • Input validation (image type, 15 MB limit, parameter ranges), thread-safe inference, interactive API docs at /docs.
  • 8 automated API tests (pytest), all passing.

Dashboard

  • Image mode: drag-and-drop a road image; changing the model or the sliders re-runs detection instantly.
  • Video mode: a local dashcam video is processed frame by frame in real time while it plays.
  • Webcam mode: live camera detection.
  • Statistics: detections, inference time, FPS, counts per class, detection table; download of the annotated result; reset.

On the RTX 3060 Laptop GPU, model inference takes about 12–19 ms per image (Table 5.3); a full request including upload and decoding takes roughly 50–90 ms in the browser, which is fast enough for interactive and video use.

8. Conclusion

  • Three YOLO generations were trained on the same cleaned dataset (3,841 images, 3 classes) with identical settings and evaluated on the same 429 unseen test images and hardware.
  • YOLO26s is the most accurate model (mAP50 0.654, mAP50-95 0.376, precision 0.761) and the best on the hardest class (cracks); YOLOv8s is the fastest on the GPU (84 FPS); YOLO11s is the smallest and fastest on the CPU.
  • All models are real-time on a consumer GPU and keep their accuracy after ONNX export.
  • Cracks remain the main challenge (AP50 ≤ 0.36), mostly because of thin shapes and inconsistent annotations; cleaner and more consistent crack labels would give the biggest improvement.
  • The FastAPI application makes the models usable for image-based and real-time road damage detection, with YOLO26s as the default.
